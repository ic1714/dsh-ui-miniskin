# dsh-ui-miniskin

DSH 界面美化插件：**启动动画** + **界面壁纸**。

- 启动动画：首帧绘制前就铺上品牌底图（不会先闪一下宿主的白底），带进度条，
  等宿主真的画出第一屏再淡出，任何异常都有硬兜底。
- 界面壁纸：9 套预设（含自定义图片）、深/浅两套配色、可调毛玻璃强度与遮罩，
  让宿主界面的背景"透"出来，同时保证文字对比度。
- 设置集成在 DSH 自带设置面板（`Ctrl+,` → 「界面美化」一节），改完立即生效并持久化。

> ⚠️ **素材版权声明**：启动动画中的鲸鱼图标是 DeepSeek 官方 Logo（取自 DSH
> 客户端内置的官方图形资源），版权归 DeepSeek 所有，此处仅作为品牌展示使用，
> 未包含在本项目的 MIT 许可范围内。

## 1. 安装

```powershell
# 克隆到本地
git clone https://github.com/ic1714/dsh-ui-miniskin.git

# 用软链装进你的 profile（改源码立即生效；也可以把路径换成 npm 包名）
dsh plugin --profile desktop add link:<克隆后的目录绝对路径>
```

装好后重启客户端（桌面端需要**完全退出重开**），打开 设置 → 界面美化 即可使用。

## 2. 生效方式

| 改了什么 | 怎么生效 |
|---|---|
| `assets/widget.js`（前端本体） | 重载页面。**桌面端没有刷新按钮** → 完全退出并重开客户端，或 F12 → `location.reload()` |
| `lib/index.js`（宿主半边） | 重启客户端 |
| 偏好文件（`~/.dsh/.dsh-ui-miniskin.json`） | **不用重启**：页面每 2 秒拉一次偏好并热应用 |

> 桌面端**不是** Ctrl+F5。DSH 自己的文案是 `desktop-reload: "重新启动 Harness"`。

## 3. 使用

**不再自带悬浮面板**：设置集成在 DSH 自己的设置面板里。
打开方式与宿主一致 —— 桌面端 **Ctrl+,**，或侧栏底部「设置」，
导航里会多出一节 **「界面美化」**（注册在官方 `settings.section` 槽上，
与常规/模型/插件/Agent 预设并列）。

| 分组 | 项目 |
|---|---|
| 壁纸 | 9 个预设缩略图（极光/星云/暮色/深海/森野/樱雾/素纸/碳纤/自定义图片） |
| | 遮罩深度 0-70（在壁纸上压暗色，越大越暗、文字越稳） |
| | 壁纸饱和 0-160（对内置渐变预设生效；自定义图片无法调饱和） |
| | 界面透明 0-100 · 毛玻璃模糊 0-32（给输入卡片加磨砂） |
| | 四周暗角开关 · 启用壁纸开关 |
| 标题栏 | **标题栏融入壁纸**开关：把窗口最上方 40px 的标题栏底色设成透明，露出下面的壁纸，右上角系统按钮浮在皮肤上 |
| 壁纸配色 | 跟随宿主 / 强制深色 / 强制浅色 |
| 自定义图片 | 「选择文件…」从本地选图（自动存进插件目录），文字颜色自动跟随图片亮度：深图浅字、亮图深字 |
| 启动动画 | 开关 · 最短停留 0-3000ms · 标题栏条带三档 · 立即重播一次 |

改完立即写入并**跨重启保留**；界面本体每 2 秒拉一次偏好，所以 2 秒内自动生效
（标题栏与启动动画在启动最早期绘制，需要重启客户端才看得到）。

偏好写在 `$DSH_HOME/.dsh-ui-miniskin.json`（默认 `~/.dsh/`），卸载插件**不会**自动删除。

### 关于「最短停留 (毫秒)」

它是**最短停留时间**，不是总时长：

```
实际显示时长 = max(这个值, 宿主首屏耗时)     // 另有 +2.6s 硬兜底，绝不会挡住界面
```

调大只会让启动动画**至少**停那么久；宿主慢的时候它会自动多等。
「立即重播」只是重载页面，**不会改动**你设的值。

### 关于右上角那三个窗口按钮

Windows 上主窗口用的是 Electron 的 `titleBarStyle:"hidden"` + `titleBarOverlay`：
那三个系统按钮（最小化/最大化/关闭）画在网页**上面**，网页改不了它们本身 ——
但它们的**底色**由宿主从 `--dsw-specific-sidebar-fill` 读出来交给主进程。

所以启动动画期间本插件把该变量钉成**与动画顶部完全同色**的不透明色
（**无条件 `#161b2f`**，因为启动动画永远是深蓝底），并在动画顶部画一条同色 40px 条带 ——
两者同色，按钮就"沉"进动画里；动画结束属性移除，标题栏交还给宿主。

> 三处容易踩错、都已修掉：
> 1. 钉的颜色**必须等于动画顶部的合成色**。一开始钉的是系统兜底色 `#1b1b1c`，
>    而渐变顶部是 `#161b2f` —— 颜色不一致，按钮反而坐在一块异色块上，更显眼。
> 2. 钉的位置**必须是 `body`**。宿主把主题令牌定义在 `body{…}` /
>    `body[data-ds-dark-theme]{…}` 上，子元素继承的是 body 的值；
>    只写 `html[data-dshb-splash]` 会被 body 的定义直接盖掉。
> 3. **无条件钉深色，不跟随系统主题**。曾按系统主题分深浅两套 —— 实测在
>    「系统浅色 + 应用深色」的组合下，标题栏被钉成浅色、按钮带着深色图标
>    坐在深蓝动画上方，看起来就是"还是原来的颜色"。浅色变体已删除。

面板里的「标题栏」三档：**同色条带**（默认）／融入动画／不画条带。
条带在启动最早期绘制，所以改动**需要重启客户端**才看得到。

### 想自己验证标题栏这条？

```
http://127.0.0.1:<port>/dsh-ui-miniskin/titlebar-probe.html
```

打开方式很关键：路由受宿主的**会话鉴权栅栏**保护，未带会话凭据的裸请求会直接返回
`rejected`（401）—— 这不是接口坏了。必须先在**同一个浏览器**里用带 token 的地址
访问一次实例，拿到会话 cookie，再打开上面的地址：

```
http://127.0.0.1:<port>/?token=<启动时打印的 token>      # 先访问这个
http://127.0.0.1:<port>/dsh-ui-miniskin/titlebar-probe.html   # 再打开自检页
```

（桌面端 `<port>` 是 `19387`；自建 profile 用启动日志里 `dsh web:` 那行给出的端口与 token。）

这页用与宿主 preload **完全相同**的取色算法，把实际会经 IPC 交给主进程的
`color` / `symbolColor` 算出来并给出结论，还带一块「条带 vs 渐变」的目视对比。

### 界面怎么"透"出来

固定使用**壁纸内嵌**：把壁纸画在宿主自己的表面上（宿主元素保持不透明，
底色变成 `rgba(底色, α)` 再叠上壁纸）。不动层叠、不动布局 ——
侧栏按钮位置、滚动都不受影响，是踩过"透明化 + backdrop-filter"各种坑之后
留下来的唯一稳法。旧版的「界面处理」档位选择器已从设置面板移除。

### 自定义图片

预设格选**「自定义」**（最后一块），然后两种方式二选一（都写进同一个偏好，不会打架）：

1. **选择文件**（推荐）：点「选择文件…」→ 系统文件对话框选一张本地图。
   插件会把图片**复制进自己的目录**（`$DSH_HOME/.dsh-ui-miniskin-images/`），
   并回给页面一个**相对路径**（`/dsh-ui-miniskin/image/…`）——
   原文件以后移动/删除都不影响壁纸，重启也在。
2. **填地址**：同源图片地址直接填。注意：**外网 `https://…` 图片会被宿主的
   安全栅栏拦截**（桌面端页面跑在 `dsh-app://` 自定义协议上，外域请求按
   cross-site 403 拒掉，连 `<img>` 都加载不了）。手动 `file:///C:/…` 同样受限，建议用方式 1。

图片会 cover 裁满整个窗口；上限 16MB；**加载失败自动退回极光渐变**并记一条自报；
没填地址就选「自定义」同样退回渐变兜底（不会白屏）。
注意：「壁纸饱和」对自定义图片无效（位图无法调饱和度）。

## 4. 配置项全表

```jsonc
{
  "wallpaper": true,      // 总开关
  "preset": "aurora",     // aurora|nebula|dusk|ocean|forest|sakura|paper|carbon|image
  "mode": "auto",         // auto=跟随宿主主题；dark/light=强制走那一套壁纸配色
  "image": "",            // preset=image 时的图片 URL
  "dim": 22,              // 深色遮罩 0-70
  "saturate": 100,        // 壁纸饱和度 0-160
  "transparency": 44,     // 界面透明度 0-100（越大壁纸越透出来）
  "blur": 14,             // 毛玻璃模糊 0-32 px（给输入卡片加磨砂）
  "surface": "embed",     // 已废弃字段：固定 embed，忽略此值
  "vignette": true,       // 四周暗角
  "splash": true,         // 启动动画
  "splashMs": 1100,       // 最短停留时间（实际 = max(本值, 宿主首屏耗时)）
  "splashLogo": true,     // 显示 Logo 标记
  "splashBar": true,      // 显示进度条
  "splashText": "",       // 自定义副标题（留空用内置文案）
  "titlebar": "flat",     // 启动动画顶部条带：flat|gradient|none

  // 开发期调试开关（正常使用保持 false）
  "probe": false          // true = dump 一次宿主 DOM 结构到自报通道
}
```

> `mode` **不改变宿主主题**，只决定壁纸与毛玻璃用哪一套配色。
> 宿主主题是系统驱动的（`data-ds-theme-source=system`），要换主题请用宿主自己的设置。
> 若 mode 与宿主主题不一致，会出现「浅色壁纸 + 宿主近白色文字」这种低对比组合。

## 5. 内置的自检通道（无浏览器控制时特别有用）

| 路由 | 作用 |
|---|---|
| `GET /dsh-ui-miniskin/health.json` | 插件版本、前端文件是否存在、当前偏好、自报条数 |
| `GET /dsh-ui-miniskin/prefs.json` | 当前偏好 + 可选预设 + 默认值 |
| `POST /dsh-ui-miniskin/prefs.json` | 合并写入偏好（字段白名单 + 清洗） |
| `GET/POST /dsh-ui-miniskin/report.json` | 界面自报：挂载几何、层是否就位、令牌是否解析、错误 |

自报通道回答的问题：**它渲染了吗？画在哪？令牌解析了吗？有没有报错？**
把 `probe` 设为 `true` 会额外 dump 宿主 DOM：不透明底色的元素、覆盖率、
关键表面的计算后背景、以及**文字对比度**（把「读不读得清」变成数字）。

## 7. 排障速查
| 现象 | 先看什么 |
|---|---|
| 设置里没有「界面美化」一节 | 看自报 `settings-section-ledger`：宿主设置导航应包含 `ui-beautify`；没有则是客户端模块没加载（改了 `client.js`/`package.json` 要**重启客户端**） |
| 壁纸看不见 / 只有一块区域有色 | 把 `probe` 设为 `true`，读 `report.json` 的 `surfaces`：哪个 `bgImage` 是 `none`，那块就没被铺到 |
| 切换预设没反应 | 同一个 `surfaces` 里的 `bgImage` 应随预设变化；若不变，说明偏好没到页面（看 `health.json` 的 `prefs.preset`） |
| 侧栏按钮位置不对 / 元素重叠 | 看 probe 的 `layout` 与 `overlap(button,whale)`；`backdrop-filter` 是首要嫌疑 |
| 启动动画的时长没按设定值走 | 它是「最短停留」：宿主首屏快就按设定值、慢就自动多等。自报里的 `splash-shown` 会带上 `minMs`，可确认偏好是否真的到了页面 |
| 右上角三个系统按钮很显眼 | 它们由 Electron 的 titleBarOverlay 绘制；启动动画期间本插件把 `--dsw-specific-sidebar-fill` 钉成与动画顶部同色的不透明色来"融入"，若宿主改了令牌名这一招会失效 |

## 8. 实现要点（为什么这样做）

1. **注入行在 `apply()` 最开头注册**，且不依赖任何服务。
   桌面端的注入表是启动时一次性收集的，晚订阅的行永远进不了表。
2. **两行注入，顺序有意义**：
   `<head>` 里的「绘制前脚本」设置配置 + 打上 `data-dshb` + 铺启动动画骨架（
   这样从第一帧就是品牌色，不会先闪宿主白底）；`<body>` 里的小引导器再异步加载前端本体。
3. **壁纸是自建固定层，不靠 slot**：slot 会被宿主按 `:empty` / `hideChrome` / variant 条件隐藏。
4. **层序**（从下到上，全部由本插件掌控）：
   `-101` 不透明底色层（"文档画布"由我负责，避免露出 Electron 窗口的深色底）
   → `-100` 壁纸层 → `-99` 遮罩/暗角层 → `-1` 毛玻璃取色层 → 宿主界面 → 启动动画。
5. **让界面"透"出来的默认机制是「内嵌」而不是「透明」**：
   - 桌面端实测把侧栏、输入卡片改透明都没用 —— 最外层的 `.BynINW_frame`
     仍是实色 `rgb(249,250,251)`，把整个视口盖住了；
   - 所以改成**把壁纸画在宿主自己的表面上**：宿主元素保持不透明，
     只是 `background-image: linear-gradient(rgba(底色, α)), 壁纸` ——
     颜色与壁纸的叠加由浏览器完成，顺序/混合都不需要我操心；
   - `background-attachment: fixed` 让各张表面共享同一块视口对齐的底图，拼起来是完整壁纸；
   - 样式表**晚于**宿主样式表，同特异性下后者胜出，所以不必到处写 `!important`
     （但覆盖宿主已有的 `!important` 时仍需明确写出）。
6. **结构层绝不加 `backdrop-filter`**：它会创建包含块，把宿主自己的
   `position:fixed/absolute` 元素重新定位 —— 实测会把侧栏「收起」按钮顶下去压住 Logo。
   模糊只给叶子卡片。
7. **宿主表面的选择器用「哈希段+语义名」前缀**（如 `[class*="_2H3hWW_root"]`）：
   纯哈希名跨构建会变，纯语义后缀会误伤；两段一起前缀匹配既精确又稳定。
8. **深色主题的令牌定义在 `body[data-ds-dark-theme]` 上**（特异性更高），
   覆盖时必须用同样的特异性再写一遍 —— 对 `background-image` 和 `background-color` 都一样。
9. **`calc()` 里的乘法必须写 `var(--a) * 1.2`**，写成 `2 var(--a)` 是无效值、静默失效。
10. **不用 `requestAnimationFrame` 保证可见性**：实测会卡在过渡中间值。
    启动动画的入场用 CSS keyframes `forwards`，淡出与兜底用 `setTimeout`。
11. **宿主首屏判据**：`[class*="_boot_"]` 从 DOM 消失，或 `#root` 出现 >240×240 的子元素；
    另加 `splashMs + 2.6s` 硬兜底 —— 动画绝不能挡住界面。
12. **可被页面热更新的规则写在样式表里，不写在 `element.style` 上**：
    早先把壁纸图放在 `root.style.setProperty('--dshb-wall-image', …)`，
    结果切换档位时样式表里的规则被正确移除了、但宿主元素上的图还在（残留壁纸）。
    凡是要跟着模式走的，一律由 `applyStyle()` 统一生成。
13. **设置走官方 slot 路线**（`client.js` + `dsh.client` 清单）：注册进宿主的
    `settings.section` 槽 = 设置导航里的「界面美化」一节，与常规/模型/插件并列；
    槽的 `inject.hooks` 会变成组件的 `useX(selector)` 属性（useSyncExternalStore 绑定）。
    这条路线只用来放设置，**常驻视觉效果仍走注入式**——两个机制互不干扰。
